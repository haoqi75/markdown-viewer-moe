# AGENTS.md

## Commands

```bash
pnpm install            # install deps (pnpm 12+, Node 26+; exact pins in package.json/.nvmrc)
pnpm test               # node:test via scripts/run-tests.js → also writes validation.txt (gitignored)

pnpm dev                # Vite + Vue dev server on :8520
pnpm build              # Vite production build → dist/server/ (multi-file)
pnpm build:release      # Vite build + Gulp inline + minify → dist/index.release.html
gulp minify-html        # re-minify dist/index.release.html only
pnpm start               # serve dist/server/ with server.js

# tools/ workspace (moe-json-editor, React/Vite/TS config editor)
pnpm build:tools        # tools typecheck + Vite build → single tools.html, then copy to dist/tools.html
pnpm build:tools-release   # names output dist/tools-<tools-version>.html
pnpm dev:tools          # Vite dev on :3000
pnpm lint:tools         # tsc --noEmit (tools only)

# docs/ site (VitePress, Chinese)
pnpm dev:docs           # vitepress dev docs (default :5173)
pnpm build:docs         # vitepress build docs → docs/.vitepress/dist (+ pagefind index)
pnpm preview:docs       # preview the built docs site
```

`pnpm build` builds only the v2 viewer; Tools and Docs are separate targets.

Tests live in `tests/` and use Node's built-in `node:test` (no extra framework); run `pnpm test`. The only test currently covers the v2 build outputs.

## Repo layout

Three parts in one repo; `pnpm-workspace.yaml` → `packages: ['tools']`:

- root = v2 single-page viewer (Vite + Vue 3 + TypeScript + SCSS)
- `tools/` = `moe-json-editor`, React 19 + Vite 6 + Tailwind 4 SPA
- `docs/` = VitePress 2 docs site (Chinese); dependencies live in the root `package.json`

The legacy v1 viewer (Gulp + vanilla TypeScript + `src/ts`, `src/styles`, `src/index.html`) lives on the **`v1` branch**. Do not reintroduce those files on `v2preview`.

A single root `pnpm-lock.yaml` covers root + `tools/`. Toolchain pins: `packageManager: pnpm@12.23.0+sha512...` and `engines.node: >=22.22.2` in `package.json`, plus `v26.13.1` in `.nvmrc`. Keep these pins, the README badges, docs, and the lockfile in sync.

`pnpm-lock.yaml` generated by pnpm 12 has **two YAML documents**: a boot document followed by the dependency graph. Use a multi-document reader and take the last document.

## v2 viewer

| Path | Role |
|------|------|
| `src/index.html` | Vite entry HTML |
| `src/main.ts` | Mounts the Vue app and imports SCSS |
| `src/App.vue` | Current Vue app shell with the iOS Liquid Glass landing UI; migrate legacy features here incrementally |
| `src/style.scss` | Self-contained v2 viewer styles |
| `src/env.d.ts` | Vite/Vue/global version types |
| `vite.config.ts` | Vite root `src`; outDir `dist/server`; base `./` |
| `gulpfile.js` | Inlines Vite CSS/JS and linked image assets into `dist/index.release.html` |
| `server.js` | Static server for `dist/server/` |

Build pipeline:

1. `vite build` compiles `src` into `dist/server/index.html` + hashed `assets/`.
2. `pnpm build:release` then runs Gulp, inlining CSS/JS and linked images into `dist/index.release.html`.
3. Gulp's `minify-html` task calls `scripts/minify-html.js` to compress the final Release HTML; `gulp release` includes it by default.
4. The release artifact is a single minified file in `dist/`; production is multi-file in `dist/server/`.

The v2 app is currently a migration skeleton. Legacy routing, TOC, themes, about page, RAW copy, dark mode, and update checker are **not yet ported**; do not document them as currently available until they are implemented in `src`.

## tools/ build pipeline (`tools/gulpfile.js`)

- `build:html` first runs `tsc --noEmit`, then gulp runs `vite build`, inlines all `/assets/*.css` and `/assets/*.js` into one `dist/index.html`, inlines `public/icon.png` as base64, and replaces `__APP_VERSION__` with `tools/package.json` version → `tools/dist/tools.html`
- `scripts/copy-tools.js` copies it to root `dist/tools.html` (or `dist/tools-<version>.html` with `--release`) and injects the Tools icon from `tools/public/icon.png`
- `scripts/minify-html.js` minifies copied Tools HTML; it supports `tools-v*.html` globs

## Docs site (`docs/`)

VitePress 2 (alpha) Chinese documentation site, published at <https://docs.moe520.cc.cd/>.

| Path | Role |
|------|------|
| `docs/src/` | Markdown content: `index.md`, `guide/`, `config/`, `about.md` |
| `docs/src/public/` | Static assets copied as-is |
| `docs/.vitepress/config.mts` | `srcDir: ./src`, `outDir: ./.vitepress/dist`, `cleanUrls`, zh-cn nav/sidebar, pagefind search |
| `docs/.vitepress/theme/` | Extends the default theme; Catppuccin + local styles |

- Docs dependencies live in the **root** `package.json`.
- `build:docs` is separate from `pnpm build`; search indexing uses pagefind.
- **Termux/Android limitation**: pagefind has no `android-arm64` binary, so `pnpm build:docs` fails at the pagefind step on this machine. Use Linux/macOS/Windows or CI.
- Many docs pages still describe v1 APIs/features. Update them as v2 features are migrated.

## CI workflows (`.github/` and `.forgejo/`)

Both dirs contain `release.yml` + `static.yml`; shared build steps should stay in sync, but deploy/publish steps are platform-specific.

- Both use `actions/checkout@v7`.
- GitHub workflows use `pnpm/setup@v3` with `cache: true`.
- Forgejo workflows use `actions/setup-node@v7` (`node-version-file: .nvmrc`) plus `pnpm/action-setup@v6` (`run_install: true`, `cache: true`).
- Both run `pnpm test` before building and append `validation.txt` / build info to the step summary.
- `release.yml` triggers on `push tags: ['v*']` or `workflow_dispatch`.
- `static.yml` currently targets the `v1` branch and legacy Pages layout; retarget it to `v2preview` / `dist/server` when v2 deployment is ready.
- After pushing a branch or tag, do **not** poll CI or verify that the Release/Pages deployment succeeded unless the user explicitly asks; treat the push as the handoff point.
