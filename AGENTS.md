# AGENTS.md

## Commands

```bash
pnpm install            # install deps (pnpm 12+, Node 26+; exact pins in package.json/.nvmrc). Run at repo root — workspace installs tools/ too
pnpm typecheck          # tsc --noEmit -p tsconfig.viewer.json (main viewer TypeScript)
pnpm test               # node:test via scripts/run-tests.js → also writes validation.txt (gitignored)
pnpm build              # page + tools + 404 → dist/
pnpm dev                # clean + build + browser-sync watch on :8520 (NOT http-server)
pnpm build:release      # build + node scripts/release.js → dist/index.release.html
node scripts/release.js # standalone: dist/index.html → dist/index.release.html
pnpm build:404          # scripts/build-404.js → dist/404.html

# tools/ workspace (moe-json-editor, React/Vite/TS config editor)
pnpm build:tools        # tools vite build → single tools.html, then copy to dist/tools.html
pnpm build:tools --release   # names output dist/tools-<tools-version>.html (from tools/package.json)
pnpm dev:tools          # vite dev on :3000
pnpm lint:tools         # tsc --noEmit (tools only; root uses pnpm typecheck)

# docs/ site (VitePress, Chinese)
pnpm dev:docs           # vitepress dev docs (default :5173)
pnpm build:docs         # vitepress build docs → docs/.vitepress/dist (+ pagefind index)
pnpm preview:docs       # preview the built docs site
```

`pnpm build` does **not** include docs; docs is a separate target.

Tests live in `tests/` and use Node's built-in `node:test` (no extra framework); run `pnpm test`. The root viewer is checked with `pnpm typecheck`; `pnpm lint:tools` runs `tsc --noEmit` for the tools workspace. There is no formatter.

## Repo layout (pnpm workspace)

Three parts in one repo; `pnpm-workspace.yaml` → `packages: ['tools']`:
- root = single-file Markdown viewer (TypeScript + SCSS + Gulp/esbuild)
- `tools/` = `moe-json-editor`, a React 19 + Vite 6 + Tailwind 4 SPA that generates `src/config.json`
- `docs/` = VitePress 2 docs site (Chinese); its dependencies live in the **root** `package.json`, not a separate workspace package

A single root `pnpm-lock.yaml` covers root + `tools/` (`tools/pnpm-lock.yaml` was removed). Toolchain is pinned twice: `packageManager: pnpm@12.20.0+sha512...` in `package.json` and `v26.13.1` in `.nvmrc`. GitHub CI resolves them with `pnpm/setup@v3`; Forgejo CI uses `actions/setup-node@v7` + `pnpm/action-setup@v6`. Keep these pins, the README badges, docs, and the lockfile in sync when bumping versions.

`pnpm-lock.yaml` generated by pnpm 12 has **two YAML documents**: a boot document (pnpm pin / config dependencies) followed by the project dependency graph. Don't delete or reorder the first document; tools that parse the lockfile must use a multi-document reader and take the last document.

`pnpm-workspace.yaml` also configures pnpm 12 behaviour:
- `allowBuilds`: allows `esbuild` / `protobufjs`, blocks `@google/genai` / `@parcel/watcher` (VitePress dependency)
- `permissions.dotenv.skills: [dotenv, dotenvx]` + `skills.dirs` (`.agent`, `.agents`, `.claude`, `.cursor`, `.gemini`, `.github`): after `pnpm install`, pnpm symlinks skills shipped by dependencies (currently `dotenv` / `dotenvx` from the `dotenv` package) into those dirs. Each dir tracks only a `.gitignore`; the symlinks are generated and ignored — never commit or hand-edit them, change `pnpm-workspace.yaml` instead.

## Architecture (root viewer)

Single-file Markdown viewer. `src/` → gulp → `dist/index.html` (all assets inlined as data URIs).

| File | Role |
|------|------|
| `src/index.html` | HTML template with placeholders (`<config-placeholder>`, `logo-placeholder`, `mascot-placeholder`, `<about-page-template>`) |
| `src/about.html` | About page source; gulp extracts `ABOUT_CONTENT_*` body + `#about-page-style` CSS and embeds it as `<template id="about-page-template">` in `index.html` |
| `src/ts/` | TypeScript modules: `config`, `router`, `toc`, `render-utils`, `about-page`, `renderer`, `version`, `update-checker`, `main`; esbuild bundles `main.ts` |
| `src/style.scss` | SCSS entry; `@use`s the partials in `src/styles/` (Dart Sass) |
| `src/styles/` | SCSS partials: base, decorations, toc, content, responsive, callouts, image-preview |
| `src/config.json` | User-configurable defaults (optional — gulpfile has DEFAULTS fallback) |
| `scripts/release.js` | Creates `dist/index.release.html` with editable JSON block at top |

## Build pipeline (gulpfile.js)

1. Read `config.json` (missing/corrupt → use `DEFAULTS` constant, not fail)
2. Deep-merge each field: config value → DEFAULTS value
3. Images: config path → DEFAULTS path → **fail build** if default also missing
4. Compile `style.scss` (Dart Sass) and bundle `src/ts/main.ts` (esbuild, IIFE, minified); minify CSS with clean-css
5. Read `about.html`, extract the `ABOUT_CONTENT_START/END` body and `#about-page-style` CSS, replace `__VERSION_DISPLAY__` (`vX.Y.Z(shortHash)`, same as footer), `__APP_VERSION__`, `__NODE_VERSION__`, `__PNPM_VERSION__`, `__GULP_VERSION__`, `__GIT_HASH__` and the mascot URL (data URI), embed as `<template id="about-page-template">`; the about icon keeps `img/favicon.svg` and `renderAbout()` reuses the already-inlined `<link rel="icon">` at runtime
6. Replace placeholders in `index.html` → inject minified CSS/JS + about template → htmlmin → `dist/index.html`
7. Extra config fields injected into `__CONFIG__`: `errorMascot`, `loadingMascot`

## Config resolution order

1. `config.json` fields
2. `DEFAULTS` in gulpfile (per-field fallback, deep merge)
3. At runtime: `<script id="release-config">` block overrides `defaultUrl` and `aliases` (release builds only)

## URL routing (`src/ts/router.ts`)

- `?md=URL` — direct Markdown URL (highest priority)
- `?p=about` — built-in about page, rendered from the embedded `<template id="about-page-template">`; takes precedence over aliases and works in release builds too
- `?p=alias` — lookup in `CONFIG.aliases` (case-insensitive)
- Hash (`#heading`) — reserved for anchor navigation, NOT alias routing
- Relative image/link URLs resolved against markdown document URL via `new URL(relative, docUrl)`

## Key rendering sequence (in `Renderer.load()`)

Order matters — don't reorder:

1. Fix relative image/link `src`/`href`
2. Broken image detection → `replaceBrokenImg()` (replaces `<img>` with `<span class="img-error">`)
3. `Prism.highlightAll()`
4. `TOC.generate()` — assigns heading IDs (slug from text, no `heading-` prefix)
5. `interceptAnchors()` — internal `#heading` links use smooth scroll + `pushState`
6. `setupImagePreview()` — skips images inside `<a>` and error placeholders
7. Hash scroll: wait for all images, decodeURIComponent, then scroll + highlight

`Renderer.load()` short-circuits to `renderAbout()` for `__ABOUT_PAGE__` before any fetch: it clones `#about-page-template` into `#content`, then runs anchors/TOC/image-preview/scroll-spy.

## Scroll & hash gotchas

- `history.scrollRestoration = 'manual'` at top of `src/ts/main.ts`
- Scroll spy (`IntersectionObserver`) suppressed for 2s after activation to avoid overwriting init hash
- `breaks: false` in `marked.parse()` — matches GitHub README rendering (single LF = space, not `<br>`)

## tools/ build pipeline (`tools/gulpfile.js`)

- `build:html` (gulp) runs `vite build`, then inlines all `/assets/*.css` and `/assets/*.js` into one `dist/index.html`, inlines `public/icon.png` as base64, and replaces `__APP_VERSION__` with `tools/package.json` version → `tools/dist/tools.html`
- `scripts/copy-tools.js` then copies it to root `dist/tools.html` (or `dist/tools-<version>.html` with `--release`) and injects favicon `<link>` tags from `src/config.json`

## Docs site (`docs/`)

VitePress 2 (alpha) Chinese documentation site, published at <https://docs.moe520.cc.cd/> (per README).

| Path | Role |
|------|------|
| `docs/src/` | Markdown content: `index.md`, `guide/`, `config/`, `about.md` |
| `docs/src/public/` | Static assets copied as-is (favicon, icon, screenshots) |
| `docs/.vitepress/config.mts` | Site config: `srcDir: ./src`, `outDir: ./.vitepress/dist`, `cleanUrls`, zh-cn nav/sidebar, pagefind search |
| `docs/.vitepress/theme/` | Extends the default theme; imports `@catppuccin/vitepress/theme/mocha/pink.css` + local `style.css`; adds floating emoji decorations |

- Docs dependencies live in the **root** `package.json`: `vitepress@2.0.0-alpha.21`, `vitepress-plugin-pagefind` + `pagefind`, `@catppuccin/vitepress`, `sass`. `vitepress-theme-sakura` is declared but not currently imported by the theme.
- Search is pagefind: the plugin runs `npx pagefind` in a `buildEnd` hook, so the index is generated only in `docs/.vitepress/dist/pagefind`. The homepage opts out via `pagefind-indexed: false`.
- Output `docs/.vitepress/dist` and `docs/.vitepress/cache` are gitignored. `build:docs` is separate from `pnpm build`.
- **Termux/Android limitation**: pagefind has no `android-arm64` binary, so `pnpm build:docs` fails at the pagefind step on this machine (VitePress page rendering itself succeeds). Use Linux/macOS/Windows or CI for a complete build.
- CI currently does **not** build or deploy docs; only the viewer/tools `dist/`.
- Docs content lives in `docs/src/`; when changing config fields or build commands, update the matching page under `docs/src/config/` or `docs/src/guide/` too.

## CI workflows (`.github/` and `.forgejo/`)

Both dirs contain `release.yml` + `static.yml`; shared build steps should stay in sync, but deploy/publish steps are platform-specific (GitHub vs Codeberg).

- Both workflows use `actions/checkout@v7`.
- GitHub workflows use `pnpm/setup@v3` with `cache: true`; it installs pnpm from `packageManager`, Node from `.nvmrc`, and dependencies — there is no separate install step.
- Forgejo workflows use the Forgejo-native `actions/setup-node@v7` (`node-version-file: .nvmrc`) plus `pnpm/action-setup@v6` (`run_install: true`, `cache: true`), which installs pnpm and dependencies.
- Both run `pnpm test` before the build; test failures stop deployment/release. `validation.txt` and the build output file list are appended to `$GITHUB_STEP_SUMMARY` (Forgejo also exposes this name, plus `$FORGEJO_STEP_SUMMARY`).
- `release.yml`: on `push tags: ['v*']` or `workflow_dispatch` → `build:release` + `build:tools --release` → uploads `dist/index.release.html`, `dist/tools-v*.html`, and `dist/files-md5.txt` to Releases. The release body is generated from `git log` since the previous tag (or from `changes_description` on manual dispatch).
- `static.yml`: on `push` to `main` → `pnpm build` (page + tools + 404) → deploys `dist/` to GitHub Pages / Codeberg Pages.
- Neither workflow builds or deploys `docs/`; the docs site is published separately.
- After pushing a branch or tag, do **not** poll CI or verify that the Release/Pages deployment succeeded unless the user explicitly asks; treat the push as the handoff point.

## Image handling interactions

- Relative URL fix runs first (rewrites `src` before anything else reads it)
- `img.closest('a')` check prevents preview on linked images
- Error and loading mascots (`error.png`, `loading.png`) are converted to data URIs by gulp and injected into `__CONFIG__`
